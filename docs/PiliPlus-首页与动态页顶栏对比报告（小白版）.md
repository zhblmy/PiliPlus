# 首页 / 动态页 顶栏实现对比报告（小白版）

> 面向不熟悉 Flutter 内部机制的读者。全文只讲两件事：**以前是怎么做的**、**现在是怎么做的**，
> 以及各自**好在哪里、差在哪里**。
> 对比对象：`e90112c93`（重构前的版本）→ 当前工作区（未提交的改动）。
> 中间还有一版 `fad6bbbd1`（只做了「缩小每帧重建范围」的性能收窄，逻辑没变），会在合适的地方顺带提到。

---

## 0. 一句话结论

| | 重构前 | 现在 |
| --- | --- | --- |
| 顶栏怎么收起 | 用一个**全局共享的数值** `barOffset` 记进度，滚动时不断改它，界面跟着它动 | 用一个**页面自己私有的数值** `_barCollapse` 记进度，由**滚动通知**或**滚动方向**驱动 |
| 内容怎么给顶栏让位 | 每次进度变化都改「内容上方的空白高度」 | 空白高度是**固定**的；让位由**滚动本身**完成（同步模式），或让位跟着收起动画收缩（即时模式） |
| 每帧要重建多少东西 | 首页：整个玻璃顶栏；动态页：**整个页面** | 只有「搜索栏那一层包装」或「UP 面板裁切那一层」 |
| 收尾（松手后补到端点） | `Timer.periodic` 每 16 毫秒改一次数值 | 原生 `ScrollController.animateTo` |
| 手感 | 只在**手指拖动**时跟手，惯性滑动期间会「冻住」 | 同步模式：**惯性也跟手**；即时模式：按方向两态收起/出现 |
| 两个模式（同步/即时） | 两套完全不同的代码，即时模式对顶栏基本没效果 | 共用**同一条链路**，只换「进度从哪来」 |

## 1. 先扫盲：这份报告里会出现的几个词

| 名词 | 白话解释 |
| --- | --- |
| **玻璃顶栏** | 首页最上面那条「搜索框 + 消息 + 头像 + 分类 Tab」；动态页最上面那条「分类 Tab + 关注的 UP 面板」。它是**浮**在列表上方的半透明模糊层（`LiquidGlass`），不是列表的一部分 |
| **让位（inset）** | 列表内容不能一开始就被玻璃盖住，所以列表最前面要有一段空白，高度 = 玻璃的高度。这段空白就叫让位 |
| **收起进度** | 一个数字：0 = 顶栏完全展开（搜索栏可见），52（首页）/ 76（动态页）= 完全收起（只剩状态栏和分类 Tab 栏） |
| **同步模式** | 设置里「顶/底栏收起类型 = 同步」：顶栏高度**跟着手指走的距离**一点点收，像窗帘被拉着走 |
| **即时模式** | 设置里选「即时」：只看**方向**——手指往上滑（内容往上走）就整体收起隐藏；手指往下滑就整体出现 |
| **`Obx` / Rx** | GetX 的「自动刷新」机制。`Rx` 是个可以被监听的数值，`Obx` 包起来的那块界面，数值一变就会**重新构建**（重新跑一遍布局和绘制） |
| **`BackdropFilter`** | 毛玻璃效果的底层实现。它是「**取它下面已经画好的内容**来做模糊」——所以它下面必须真有内容，也不能隔着一层不透明的板子 |
| **pinned sliver** | 滚动列表里「粘在顶部不走」的一块区域（类似通讯录的字母吸顶）。重构中间试过用它，最后删掉了 |
| **`correctBy`（偷滚动）** | 一个技巧：改完「上方空白高度」后，偷偷把滚动位置也改一点点，让画面看起来没跳 |
| **`Timer.periodic`** | 定时器：每隔固定时间执行一次。用它做动画意味着**即使界面没变化也在唤醒 CPU** |

## 2. 首页（搜索栏 + 分类 Tab）

### 2.1 重构前是怎么做的

结构（页面最外层）：

```
Stack
├── Positioned.fill(  TopBarInset( 高度随手势变化的让位 ) → body(各分类 Tab 页)  )
└── Positioned(top:0,  Obx( 玻璃顶栏：状态栏 → 搜索栏 → 分类 Tab 栏 )  )      ← 整块被 Obx 包着
```

数据流（一次手指拖动）：

1. 手指滑动列表 → Flutter 发出滚动通知（`ScrollUpdateNotification`）。
2. `common_page.dart` 的 `onNotificationType2` 收到通知，**只认「手指拖动」**（`dragDetails != null`），
   把差值累加到**全局共享**的 `MainController.barOffset`（一个 Rx 数值，量程 0~52）。
3. 首页的搜索栏包装层读到 `barOffset`，算出「搜索栏当前高度 = 52 − barOffset」，同时把内容往上挪、
   外面套 `ClipRect` 裁掉超出的部分。
4. 为了让列表「看起来没动」，首页还额外开了 `needsCorrection = true`：每帧用
   `Scrollable.position.correctBy(...)` **偷改滚动位置**，抵消掉「上方空白变矮」带来的位移。
5. 手指抬起 → `ScrollEndNotification` → 启动 `Timer.periodic(16ms)`，用 220ms 的 `easeOutCubic`
   把 `barOffset` 补到 0 或 52（这样顶栏不会停在半路）。
6. 首页的让位 `TopBarInset(value: 随手势变化的高度)` 也是每帧在变，所以**每个分类 Tab 页每帧都会重新排一次版**。

即时模式（选「即时」时）走的是另一套：`showTopBar` 这个 Rx 布尔值 + `AnimatedOpacity` +
`AnimatedContainer(500ms)`。

### 2.2 重构前：优点

1. **能用，而且「跟手」**：手指拖动期间，顶栏高度和手指 1:1，观感自然。
2. **不会停在半路**：抬手后有 220ms 补间，收起到端点。
3. **玻璃的视觉已经做好了**：模糊、半透明、高光边、盖住状态栏。

### 2.3 重构前：缺点（以及你会感觉到什么）

| 缺点 | 技术上发生了什么 | 你会感觉到什么 |
| --- | --- | --- |
| 惯性滑动时顶栏「冻住」 | `onNotificationType2` 只处理「手指拖动」的通知，惯性滑动（甩一下）期间不更新 | 甩一下列表，顶栏不动，直到停下来才靠补间「跳」到位 |
| 两个页面互相干扰 | `barOffset` 是**全局共享**的一个数值，首页、动态页、我的页都在写 | 偶尔出现「栏的状态和列表对不上」 |
| 首页每帧重建整块玻璃 | 玻璃顶栏整块被 `Obx` 包住，`barOffset` 一变就重建 → 每帧重新构造并绘制毛玻璃 | 滑动时更容易掉帧、发热（毛玻璃本身很贵） |
| 动态页更严重 | 动态页是 `Obx(page)` —— **整个页面**每帧重建 | 动态页滑动明显更吃力 |
| 每个分类页每帧重排 | 让位 `TopBarInset` 的值每帧在变，等于告诉所有分类页「让位高度变了」 | 滑动时整页都在重新排版 |
| `correctBy` 是个 hack | 一边改空白高度、一边偷改滚动位置 | 极端情况下（惯性 + 补间同时进行）会有轻微跳动或和弹道模拟打架 |
| `Timer.periodic` 常驻唤醒 | 补间期间每 16ms 执行一次 | 耗电（幅度不大，但没必要） |
| 即时模式对顶栏基本没用 | 即时模式那套是 `showTopBar` + `AnimatedContainer`，和同步模式是两套逻辑 | 选「即时」和选「同步」在顶栏上表现差不多，甚至没反应 |

### 2.4 现在是怎么做的

结构：

```
Stack
├── Positioned.fill(  TopBarInset( 常量高度 + 收起进度 collapse ) → body(各分类 Tab 页)  )
└── Positioned(top:0,  玻璃顶栏 )        ← 静态实例，不再被 Obx 包住
```

每个分类 Tab 页的滚动列表最前面，放一个**只占位置、什么都不画**的 sliver（`TopBarInsetSpacer`）：

- 同步模式：它的高度**固定** = 玻璃展开时的高度（比如 94）。
  于是「内容顶部 = 94 − 已滚动距离」，让位完全由**滚动本身**完成 —— 不需要任何补偿技巧。
- 即时模式：它的高度 = `玻璃展开高度 − 收起进度`，跟着收起动画一起收缩。

数据流（一次手指拖动）：

1. 滚动通知到达首页/动态页自己的监听器。
2. 用 `Scrollable.maybeOf(notification.context)?.position` 判断「这条通知是哪个列表发的」：
   只认当前可见 Tab 的那个列表（保活的其它 Tab、卡片里内嵌的小列表、UP 面板都不会把顶栏带偏）。
3. 然后按模式二选一：
   - **同步**：`collapse = 该列表的滚动位置`（惯性滑动也会收到通知 → 跟手 1:1）；
   - **即时**：只看 `UserScrollNotification` 的方向 —— 上滑 → 收起，下滑 → 出现；
     用 220ms `easeOutCubic` 的 `AnimationController` 把 `collapse` 从 0 动画到 52（或反过来）。
4. 把 `collapse` 写进一个**页面私有的** `ValueNotifier`，然后：
   - 玻璃顶栏读它 → 「搜索栏当前高度 = 52 − collapse」；
   - 让位 sliver 读它（仅即时模式）；
   - 排行榜左侧的竖排分类栏也读它（跟着顶栏一起上移，不会留白）。
5. 松手（同步模式）：`ScrollEndNotification` + 本次是上滑 → 用原生
   `ScrollController.animateTo(52, 220ms, easeOutCubic)` 补到端点；下滑则补回 0。

### 2.5 现在：优点

1. **取消了三个「脏」做法**：没有 `Timer.periodic`、没有 `correctBy` 偷滚动、没有全局共享的进度值。
2. **每帧重建范围极小**：只重建「搜索栏那一层包装」（高度 + 位移），玻璃（`BackdropFilter`）和搜索栏内容都是静态实例。
3. **惯性也跟手**（同步模式）：因为用的是滚动通知而不是「手指拖动」判定。
4. **玻璃和让位严格同源**：都从同一个 `collapse` 算出来，不会出现「让位比玻璃少一点、漏出一条背景」。
5. **两个模式共用一条链路**，只换「进度从哪来」，不会再出现「选即时没反应」。
6. **每个分类页不再每帧重排**：`TopBarInset` 的值变成常量，不会每帧通知所有页面。
7. **排行榜左侧分类栏**从「每帧重排整个分区页」缩到「只重建那一层包装」。

### 2.6 现在：缺点 / 代价（也说清楚）

| 代价 | 说明 |
| --- | --- |
| 即时模式是「两态」的 | 它不看滚动位置：只要你往上滑，顶栏就整体收起（而不是按比例收一半）。这正是你要的「上滑收起隐藏、下滑出现」 |
| 同步模式下滑方向的补间会「归位」 | 松手后回到展开态，列表也会被带回顶部附近（幅度 ≤ 52 像素，观感是「松手归位」） |
| 让位不再是「pinned」 | 实测 pinned 与普通占位 sliver 的几何完全等价，所以删掉了 pinned 头（更简单、少一层固定区域） |
| 需要重启才换模式 | 这是原本设置项的行为（设置页里也写了「重启生效」） |
| 有一处「必须满足的前提」 | 每个分类 Tab 的可见列表，必须用「该 Tab 自己的控制器」；否则同步模式下顶栏不会跟着它收（现在各页面都满足） |

## 3. 动态页（分类 Tab + 关注的 UP 面板）

### 3.1 重构前是怎么做的

结构：

```
Stack / Obx(page)               ← 整个页面被 Obx 包住
├── Positioned.fill( TopBarInset( 高度随手势变化 ) → body(各分类 Tab 页) )
└── Positioned(top:0, 玻璃顶栏：状态栏 → 分类 Tab 栏 → 「顶部」UP 面板 )
```

关键差别（和首页比）：

1. **比例换算**：UP 面板高 76，而共享的 `barOffset` 量程只有 52（那是首页搜索栏的高度）。
   所以动态页必须做换算：`面板高度 = 76 × (1 − barOffset / 52)`。
   换算不精确时，收到底会**剩下一条空玻璃**（注释里就写了这一点）。
2. **整个页面被 `Obx` 包住**：`upPanelOffset == null ? page() : Obx(page)`
   → 只要在裸滚，**整页每帧重建**（这是动态页最贵的一处）。
3. 「顶部」位置的 UP 面板放进玻璃顶栏；其它位置（左侧固定/右侧固定/抽屉）用
   `Padding(top: barInset)` 自己让位，不参与顶栏收起。
4. 面板裁切：`ClipRect( CustomHeightWidget(...) )` —— 这一层是对的，保留至今。

### 3.2 重构前：优点

1. 结构对：`状态栏 → 分类 Tab 栏 → UP 面板`，且整块在分类切换动画（`TabBarView`）之外，切 Tab 时不横滑。
2. 面板能随滚动收起 / 下拉展开（虽然收得不够干净）。
3. 面板裁切正确（不会画到分类 Tab 栏上）。

### 3.3 重构前：缺点

| 缺点 | 你会感觉到什么 |
| --- | --- |
| 整页每帧重建（`Obx(page)`） | 动态页滑动比首页明显更卡、更热 |
| 76/52 比例换算 | 收起过程中内容比手指「多走」约 24 像素；偶尔收到底还剩一条空玻璃 |
| 和首页共用全局 `barOffset` | 两个页面互相干扰，状态偶尔对不上 |
| 惯性滑动期间不更新 | 甩一下列表，面板冻住，停下才跳到位 |
| 即时模式不生效 | 选「即时」时面板根本不收起（注释里直接写了「此处面板保持不变」） |

---

### 3.4 现在是怎么做的

结构：

```
Stack
├── Positioned.fill( TopBarInset( 常量高度 + collapse ) → body )
└── Positioned(top:0, 玻璃顶栏：状态栏 → 分类 Tab 栏 → UP 面板 )   ← 静态实例
```

1. **量程就是面板高度 76**，不再做任何比例换算：`面板高度 = 76 − collapse`。
2. 数据流和首页**完全一样**（同一个 `ValueNotifier`、同一条通知 → 白名单 → 同步/即时二选一）。
3. 一个卫语句保证只在「UP 面板在顶栏里」时才参与：位置必须是**顶部**，且开着「首页顶栏收起」。
4. 面板裁切仍是 `ClipRect(CustomHeightWidget(...))`，但里面装的是**静态面板实例**，每帧只重建裁切那一层。
5. 非顶部位置（左/右固定、抽屉）保持原样：`Padding(top: barInset)` 自己让位，不参与收起。

### 3.5 现在：优点

1. **比例换算彻底消失** → 收到底就是干净地收到底，不会剩一条空玻璃。
2. **不再整页重建** → 只重建面板裁切那一层；滑动时明显更省。
3. 和首页**共用一条链路**，两个页面的表现一致，也不会再互相干扰。
4. 即时模式对 UP 面板**真的生效了**（前提：面板位置设为「顶部」）。

### 3.6 现在：缺点 / 代价

| 代价 | 说明 |
| --- | --- |
| 前提：面板位置必须是「顶部」 | 只有顶部的面板才会被放进玻璃顶栏；左/右固定与抽屉是独立侧栏，本来就不该跟着顶栏收 |
| 非顶部的面板仍然不收起 | 这是有意的（侧栏收起是另一个交互） |
| 面板本体是静态的 | 面板里的 UP 列表照旧（内部自己用 `Obx` 刷），不受影响 |

## 4. 总对比表（之前 vs 现在）

| 维度 | 重构前 | 现在 |
| --- | --- | --- |
| 首页：每帧重建 | 整块玻璃顶栏（`Obx(glassTopBar)`） | 只有搜索栏那一层包装 |
| 动态页：每帧重建 | **整个页面**（`Obx(page)`） | 只有 UP 面板裁切那一层 |
| 进度值存放 | 全局 `RxDouble barOffset`（三个页面共用） | 每个页面自己的 `ValueNotifier` |
| 跟手范围 | 只有手指拖动 | 同步模式：惯性也跟；即时模式：按方向 |
| 让位方式 | 改「上方空白高度」+ `correctBy` 偷滚动 | 空白固定（滚动自己让位）/ 空白随动画收缩 |
| 让位与玻璃一致性 | 靠两套计算「尽量对齐」 | 同一个数字算出来，天然一致 |
| 收尾补间 | `Timer.periodic(16ms)` | `animateTo(220ms, easeOutCubic)` |
| 动态页量程 | 76/52 比例换算 | 直接用 76 |
| pinned sliver | 没有 | 试过又删掉（实测与普通占位等价，删掉更简单） |
| 即时模式 | 顶栏基本没效果 / 动态页完全不收 | 两个页面都生效（默认值就是它） |
| 分类页每帧重排 | 有（让位值每帧在变） | 没有（让位值变常量） |
| 排行榜左侧分类栏 | 每帧重排整个分区页 | 只重建那一层包装 |

## 5. 现在的实现有哪些「前提」要注意

1. **顶栏收起开关**：设置里「首页顶栏收起」要打开（手机默认打开）。关掉时顶栏常驻，本文所有收起行为都不发生。
2. **收起类型**：默认已改为**即时**（上滑收起隐藏、下滑出现）；想跟手 1:1 就选**同步**。**改完要重启**。
3. **动态页 UP 面板位置**：要在设置里设为**顶部**，才会进玻璃顶栏、才会跟着收起。
4. **顶栏不能隔着一层 `Material`**：玻璃是「取下面的内容做模糊」，中间隔一层不透明的板子就会变成一条纯色带。
   所以两个页面在玻璃模式下**根节点就是 `Stack`**（只有动态页的抽屉模式才套 `Scaffold`）。

## 6. 过程中踩到的坑（白话版）

1. **「不可见的占位块」不能是 0 高度**（早期用 pinned 头部时）：
   Flutter 的吸顶头部会自己算「该占多少位置」，而这个算法和里面那个块的真实高度不一致时，
   调试模式会直接报错 `SliverGeometry is not valid`。后来发现这个吸顶头部和普通占位块
   **效果完全一样**，就干脆删掉了。
2. **滚动通知里的「数据」是快照，不是本尊**：
   通知里带的 `metrics` 是复制出来的一份数据，用「是不是同一个对象」去判断
   **永远不成立** —— 上一版就因为这个，把所有滚动通知都过滤掉了，表现为「顶栏完全不动」。
   正确做法是用通知里的 `context` 反查出「是哪个列表发的」。
3. **方向通知在结束时还会再发一次 `idle`**：如果把它当成「下滑」，就会出现
   「一收起立刻又弹回来」。所以只认 `forward`（下滑→出现）和 `reverse`（上滑→收起）。
4. **列表比量程还短时会空转**：补间想补到 52，但列表一共只能滚 30，
   于是「补 → 结束 → 再补」无限循环。现在加了「已经到底就不补」的判断。
