## 二、检查方法与命令

```powershell
# 1) 列出过期的依赖（区分 direct / dev / transitive）
flutter pub outdated

# 2) 预演“在现有 pubspec 约束内”能升到哪一步（不写文件）
flutter pub upgrade --dry-run

# 3) 预演“允许修改 pubspec 版本约束”能升到哪一步（不写文件）
flutter pub upgrade --major-versions --dry-run
```

与上游对比所用命令：

```powershell
# 4) 与上游 main 比对 pubspec.yaml / pubspec.lock
git diff remotes/upstream/main -- pubspec.yaml pubspec.lock
git rev-list --left-right --count remotes/upstream/main...HEAD   # 领先/落后提交数

# 5) 逐包比对 lock 中的解析版本（解析 YAML 的 "  <pkg>:" + "    version:"）
#    结果为 diff count = 0

# 6) 校验 git 依赖实际分支头
git ls-remote https://github.com/bggRGjQaUbCoE/audio_service.git refs/heads/dev
git --git-dir=<pub git cache> log -1 --format="%H|%ad|%s" --date=iso <commit>
```

以上命令均为只读，**未修改 `pubspec.yaml` / `pubspec.lock`**。

判定口径（沿用 `flutter pub outdated` 的语义）：

- `current`：本地 `pubspec.lock` 里锁定的版本
- `upgradable`：不改 `pubspec.yaml` 时可达到的最高版本
- `resolvable`：允许改 `pubspec.yaml` 版本约束时可达到的最高版本
- `latest`：pub.dev（或 git 分支）上的最新版本

## 八、网络问题记录

本次检查过程中 `git fetch` 到 `github.com` 出现间歇性 TLS 中断：

```
fatal: unable to access 'https://github.com/<owner>/<repo>.git/':
  TLS connect error: error:0A000126:SSL routines::unexpected eof while reading
```

| 时间 | 命令 | 结果 |
|---|---|---|
| 22:37 | `flutter pub outdated` | ✅ 成功（使用本地 git 缓存） |
| 22:37 | `flutter pub upgrade --dry-run` | ❌ 连续 3 次失败（audio_session / material_design_icons_flutter / media-kit），按约定放弃 |
| 22:53 | 连通性探测 `git ls-remote` + HTTPS | ✅ github.com 200、pub.dev 200 |
| 22:53 | `flutter pub upgrade --dry-run` | ✅ 第 1 次即成功 |
| 22:53 | `flutter pub upgrade --major-versions --dry-run` | ⚠️ 第 1 次失败（canvas_danmaku），第 2 次成功 |

**结论**：不是仓库损坏、也不是 pub 缓存损坏，而是本机到 `github.com` 的 HTTPS 连接**偶发抖动**。`pub.dev` 的 hosted API 全程正常。所有失败都发生在 git 依赖的 `fetch` 阶段。

若后续频繁出现，可让 git 走代理后重试：

```powershell
git config --global http.https://github.com.proxy http://127.0.0.1:7890
```

## 九、升级建议

按风险从低到高，建议分三个独立提交：

1. **低风险**：`flutter pub upgrade`，吃掉 6 个 patch/minor 升级。
   验证：`flutter analyze` + 一次 Windows 构建 + 托盘/窗口功能手测。
2. **中风险**：`image_cropper` 13 系列，改 `pubspec.yaml` 约束。
   验证：头像/封面裁剪功能回归，含 Web 端。
3. **暂不处理**：第六节的 16 个约束冲突项、第七节的 override 项。
   这些需要上游或 fork 先动，属于长期跟进项。

> 补充：第三节的对比表明，**等上游更新并不会带来依赖变化**（252 个包版本完全一致）。因此这里不存在"等上游升级后再跟进"的选项，想升就只能自己动 `pubspec.yaml` 或等 pub.dev 上被卡的包放宽约束。
