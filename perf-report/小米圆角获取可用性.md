### **方案一：使用社区插件 `corner_radius_plugin`（推荐）**

这是目前最省事、逻辑最完整的方案，它已经封装好了 Android 12+ 与低版本系统之间的兼容逻辑。

#### **Android 端策略**

插件遵循了**“新 API 优先，旧系统回退”**的策略：

1. **Android 12 (API 31) 及以上**：直接使用官方的 `WindowInsets.getRoundedCorner(int position)` API，**能分别获取四个角各自的精确半径**。
2. **Android 12 以下**：回退去查找系统 `dimen` 资源 `rounded_corner_radius`（或其变体）。如果设备厂商（如小米）定义了这个资源，就能拿到一个近似值；如果没有定义，则返回 `0`。

#### **iOS 端策略**

iOS 并不像 Android 那样有公开的实时圆角 API。该插件通过集成 **BezelKit** 的 JSON 数据，根据当前设备型号标识符（如 `iPhone14,2`）去查找预先整理好的圆角半径数据。

#### **代码使用示例**

**添加依赖**（`pubspec.yaml`）：

yaml

```
dependencies:
  corner_radius_plugin: ^0.0.9
```

**初始化与读取**（建议在 `initState` 或 `main` 中调用一次）：

dart

```
import 'package:corner_radius_plugin/corner_radius_plugin.dart';

// 初始化，并设置一个不支持圆角设备时的回退值（如 12）
Future<CornerRadius?> _radiusFuture = CornerRadiusPlugin.init(defaultRadius: 12);

// 初始化完成后，可通过静态属性直接读取
final screenRadius = CornerRadiusPlugin.screenRadius;

// screenRadius 包含 topLeft, topRight, bottomLeft, bottomRight 四个独立的值
```

在 UI 中，你可以直接将这四个值应用到 `BorderRadius.only(...)` 中，让组件轮廓贴合屏幕物理边缘。

**需要注意**：对于**不支持**圆角或厂商未提供 `dimen` 资源的低版本 Android 设备，插件返回的四个角半径可能都是 `0`。如果你的 UI 在四角为 `0` 时显示异常，务必通过 `defaultRadius` 或 `setDefaultRadius(double)` 设置一个视觉上可接受的默认值。

### **方案二：通过 MethodChannel 自行桥接原生代码**

如果你不希望引入插件，或者需要更精细地控制原生逻辑，可以手动实现平台通道。这是理解插件内部原理的基础。

#### **Android 原生实现要点（Kotlin）**

在 `MainActivity` 的 `configureFlutterEngine` 中注册方法。核心逻辑分为两条分支：

**分支 A：Android 12+（精确，四角独立）**

kotlin

```
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
    val insets = window.decorView.rootWindowInsets
    val corners = mapOf(
        "topLeft" to insets.getRoundedCorner(RoundedCorner.POSITION_TOP_LEFT)?.radius ?: 0f,
        "topRight" to insets.getRoundedCorner(RoundedCorner.POSITION_TOP_RIGHT)?.radius ?: 0f,
        "bottomLeft" to insets.getRoundedCorner(RoundedCorner.POSITION_BOTTOM_LEFT)?.radius ?: 0f,
        "bottomRight" to insets.getRoundedCorner(RoundedCorner.POSITION_BOTTOM_RIGHT)?.radius ?: 0f
    )
    result.success(corners)
}
```

`RoundedCorner.radius` 返回的是**像素值**（`Float`），需要在 Dart 层根据 `devicePixelRatio` 转换为逻辑像素。

**分支 B：Android 12 以下（OEM 回退，近似值）**  
这正是你在前一个问题中关注的逻辑。在低版本中，无法获得四角独立值，只能尝试读取系统 `dimen`：

kotlin

```
else {
    val res = resources
    // 尝试读取四角通用的 rounded_corner_radius
    var id = res.getIdentifier("rounded_corner_radius", "dimen", "android")
    var radiusPx = if (id > 0) res.getDimensionPixelSize(id) else 0

    // 如果通用值不存在，再尝试你提到的 rounded_corner_radius_top（小米等 OEM 可能提供）
    if (radiusPx == 0) {
        id = res.getIdentifier("rounded_corner_radius_top", "dimen", "android")
        if (id > 0) radiusPx = res.getDimensionPixelSize(id)
    }

    // 低版本无法区分四角，统一返回同一个近似值
    val uniform = radiusPx.toFloat()
    result.success(mapOf(
        "topLeft" to uniform, "topRight" to uniform,
        "bottomLeft" to uniform, "bottomRight" to uniform
    ))
}
```

这里必须注意：`rounded_corner_radius_top` **并非 Android 标准资源**，而是小米等部分厂商的定制。在非小米且未定义该资源的设备上，`getIdentifier` 会返回 `0`，因此代码中必须有回退或默认值兜底。

#### **iOS 原生实现要点（Swift）**

iOS 没有公开 API 可实时查询圆角。常见的工程化做法是通过 KVC（Key-Value Coding）访问私有属性 *`displayCornerRadius`，或者依赖设备型号到圆角值的映射表。插件 `corner`*`radius_plugin` 采用的是后者（BezelKit JSON），稳定性更好。如果自行实现 KVC 方案，需要注意**上架 App Store 的审核风险**，因为访问私有 API 可能被拒绝。

### **两种方案的关键差异与选择建议**

| **维度**             | `corner_radius_plugin`         | **自行 MethodChannel**      |
| :------------------ | :------------------------------ | :------------------------- |
| **接入成本**           | 极低，添加依赖即可                      | 中高，需编写 Kotlin/Swift 代码    |
| **Android 12+ 精度** | 四角精确值                          | 取决于你的实现，可做到同样精确           |
| **低版本 OEM 适配**     | 已内置 `rounded_corner_radius` 回退 | 需要自行编写 `getIdentifier` 逻辑 |
| **iOS 支持**         | 内置 BezelKit 数据，持续更新            | 需自行维护设备型号映射，成本较高          |
| **适用场景**           | 绝大多数常规项目                       | 插件无法满足的特殊定制，或对包体有严格限制     |

对于你的场景（关注小米圆角、希望在 Flutter 中获取），**首选** `corner_radius_plugin` 是最高效的做法。它在 Android 12+ 上能给出比小米 `rounded_corner_radius_top` 更精确的四角独立值，同时在低版本小米设备上也会自动回退到系统 `dimen`，覆盖了你原始原生代码的能力范围。

  



### **🔍 先理清根本约束：各平台的能力边界**

之前的方案各有侧重，但最优解需要建立在对平台能力的精确认知上。

**Android 端：官方标准已就绪**

- **Android 12 (API 31) 及以上**：存在精确的官方 API `WindowInsets.getRoundedCorner()`，可以获取**四个角各自独立**的半径值。
- **Android 12 以下**：没有标准四角 API。你最初提到的 `rounded_corner_radius_top` 是**厂商（如小米）自定义**的 `dimen` 资源，并非通用标准，在其他设备上可能不存在，导致返回 `0`。

**iOS 端：官方 API 长期缺位，安全方案只有查找表**

- iOS **没有公开的 API** 来实时查询屏幕圆角半径。
- 社区常见做法有两种：
  1. **私有 API 风险**：通过 KVC 访问 `UIScreen` 的 `_displayCornerRadius` 属性。**这存在被 App Store 审核拒绝的风险**，不适合作为生产环境的“最优解”。
  2. **安全查找表（Lookup Table）** ：根据设备型号标识符（如 `iPhone14,2`），在预先整理的设备-圆角映射表中查找。这是目前**唯一安全且被推荐**的方案。

**Flutter 官方的新变量：**`MediaQuery.displayCornerRadii`  
Flutter 引擎已开始原生支持屏幕圆角数据。`MediaQueryData` 中新增了 `displayCornerRadii` 属性，这是一个 `BorderRadius?` 类型，表示**逻辑像素**下的圆角。但需注意：**目前该属性仅在 Android API 31+ 上被填充**，在更低版本的 Android 和 iOS 上可能为 `null`。

### **💎 最优解：分层自适应策略**

基于以上约束，最优解不是一个固定的方法，而是一个**优先级链**。它在不同平台上依次尝试最可靠的数据源，直到获得有效值。

#### **第一层：优先使用 Flutter 官方 API（未来趋势）**

对于 **Android 12+** 设备，最直接、零依赖的方式是直接读取 `MediaQuery`：

dart

```
BorderRadius? radii = MediaQuery.displayCornerRadiiOf(context);
if (radii != null && radii != BorderRadius.zero) {
  // Android 12+ 精确四角半径，直接使用
}
```

这是最“Flutter 原生”的方式，无需任何插件，且精度最高。随着 Flutter 版本更新，这将是首选的理想路径。

#### **第二层：回退到成熟的跨平台插件（当前生产环境的主力）**

当官方 API 不可用（iOS 或 Android 12 以下）时，需要回退到社区方案。综合评估后，`corner_radius_plugin` **是当前更均衡的选择**，原因在于它采用了与你约束相匹配的混合策略：

- **Android 端**：它正是采用了“**Android 12+ 官方 API，低版本回退系统** `dimen`”的逻辑，与你最初的思路一脉相承，但处理了边界情况。
- **iOS 端**：它**没有使用私有 API**，而是集成了 **BezelKit 的 JSON 查找表**，通过设备型号匹配圆角值，并设有 GitHub Action **每周自动更新**数据，兼顾了安全性与可维护性。

相比之下，`screen_corner_radius` 插件在 iOS 上使用了 `_displayCornerRadius` 私有 API，虽能工作，但引入了不可忽视的审核风险。

**使用** `corner_radius_plugin` **的代码模式：**

dart

```
// 启动时初始化一次，务必设置一个非零的回退值
Future<CornerRadius?> _radiusFuture = CornerRadiusPlugin.init(defaultRadius: 16);

// 在需要的地方获取
final screenRadius = CornerRadiusPlugin.screenRadius;
// 根据 screenRadius?.topLeft 等值构建 BorderRadius
```

#### **第三层：自定义混合方案（追求极致控制或包体优化）**

如果你希望完全掌控逻辑，或避免引入插件依赖，可以自行通过 MethodChannel 实现上述**混合策略**：

- **Android 原生**：`if (SDK_INT >= 31)` 使用 `getRoundedCorner`；`else` 尝试读取 `rounded_corner_radius` 系统 `dimen`，如果失败则返回一个合理的默认值（如 0 或 16）。
- **iOS 原生**：**自行维护或集成一份设备-圆角映射表**（可参考或定期同步 BezelKit 的数据源），通过设备型号查找。**务必避开私有 API**。

这本质上是将 `corner_radius_plugin` 的内部逻辑手动实现一遍，成本较高，但能实现最精确的控制。

### **📐 核心定义：类型与数据来源**

在 `MediaQueryData` 中，该属性的定义如下：

dart

```
final BorderRadius? displayCornerRadii;
```

它返回的是一个**可空的** `BorderRadius` **对象**，单位是**逻辑像素**。因为是 `BorderRadius`，所以它的四个角（`topLeft`、`topRight`、`bottomLeft`、`bottomRight`）可以各自拥有独立的半径值，这对于折叠屏或上下曲率不同的设备非常重要。

其底层数据源于引擎从系统硬件读取的 `DisplayCornerRadii`，该类以**物理像素**为单位记录四个角的曲率，若某个角为直角（未圆角），则对应值为 `0.0`。

### **🚨 最关键的约束：平台支持与 `null` 值**

这是使用该 API 时**必须首先处理的前提**。

> **该属性目前仅在 Android API 31（Android 12）及以上版本中被填充。在更低的 Android 版本、iOS 以及所有其他平台上，其值均为** `null`**。**

Flutter 官方在底层实现说明中也明确指出，iOS 没有公开 API 获取此数据，安全的方案只能是预先生成设备-圆角查找表，因此短期内 iOS 端不会由 Flutter 引擎直接填充此值。这意味着，**你绝不能假设它总是有值**，`null` 检查是逻辑的起点，而非事后的补充。

### **🛠️ 推荐用法：优先使用 `maybeDisplayCornerRadiiOf`**

官方推荐通过 `MediaQuery.maybeDisplayCornerRadiiOf(context)` 静态方法来获取该值，而不是直接去读 `MediaQuery.of(context).displayCornerRadii`。

dart

```
// 推荐：仅在圆角数据变化时触发重建
final BorderRadius? radii = MediaQuery.maybeDisplayCornerRadiiOf(context);
```

**好处在于**：直接访问 `MediaQuery.of(context)` 会在**任何** MediaQuery 属性（如窗口大小、内边距、亮度等）变化时都触发组件重建；而 `maybeDisplayCornerRadiiOf` 是细粒度的，它**只会在** `displayCornerRadii` **这个特定属性发生变化时**才触发重建，性能更优。该方法在找不到 `MediaQuery` 祖先时返回 `null`，语义也更安全。

> **注意**：较早的资料中可能出现 `displayCornerRadiiOf`，但该名称已在后续 API 整理中被标记为废弃，统一由 `maybeDisplayCornerRadiiOf` 取代，以获得可空返回值的语义一致性。

### **💻 实战代码模式：带安全回退的完整用法**

由于 `null` 是常态，你的代码必须包含回退逻辑。一个健壮的写法如下：

dart

```
@override
Widget build(BuildContext context) {
  // 1. 尝试获取精确圆角
  final BorderRadius? systemRadii = MediaQuery.maybeDisplayCornerRadiiOf(context);

  // 2. 定义回退值（例如 16 逻辑像素）
  const BorderRadius fallbackRadii = BorderRadius.all(Radius.circular(16));

  // 3. 优先使用系统值，null 时回退
  final BorderRadius effectiveRadii = systemRadii ?? fallbackRadii;

  return ClipRRect(
    borderRadius: effectiveRadii,
    child: ColoredBox(
      color: Theme.of(context).colorScheme.surface,
      child: content,
    ),
  );
}
```

这种 `systemRadii ?? fallbackRadii` 的模式，正是官方示例和社区文章反复强调的标准做法。

### **🔬 物理像素 vs. 逻辑像素：何时用哪个？**

- `MediaQueryData.displayCornerRadii`**（逻辑像素）**：用于常规的 Widget 布局和裁剪（如 `ClipRRect`、`BorderRadius`），因为它与你的布局坐标系一致。
- `FlutterView.displayCornerRadii`**（物理像素）**：当你编写**自定义** `RenderObject`**、着色器（Shader）** 或需要进行底层像素级操作时，应使用此值，以避免手动进行 `devicePixelRatio` 换算时出错。

### **💎 总结：在“最优解”策略中的位置**

`MediaQuery.maybeDisplayCornerRadiiOf(context)` 是**第一优先级**的数据源，但它**仅覆盖 Android 12+ 这一个平台**。你的分层策略应清晰地表达为：

dart

```
BorderRadius getEffectiveCornerRadii(BuildContext context) {
  // 第一层：官方精确 API（Android 12+）
  final systemRadii = MediaQuery.maybeDisplayCornerRadiiOf(context);
  if (systemRadii != null) return systemRadii;

  // 第二层：回退到跨平台插件（覆盖 iOS 及低版本 Android）
  // 例如使用 corner_radius_plugin 的初始化结果
  // return CornerRadiusPlugin.screenRadius ?? fallback;

  // 第三层：最终安全回退
  return const BorderRadius.all(Radius.circular(16));
}
```

这个官方变量的价值在于，它为 Android 12+ 设备提供了**零依赖、最高精度、且能自动响应配置变化**的圆角数据。但它并未取代插件，而是让插件的职责更加聚焦于**填补 iOS 和旧版 Android 的空白**。两者组合，才构成了当前完整的最优工程方案。
